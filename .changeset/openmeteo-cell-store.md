Shared Open-Meteo cell store (`fetchCellVariables`): one cache entry per API, fixed parameters and 1 km cell holds every variable fetched there, each with its own fetchedAt, with separate hourly/daily/current sections. Concurrent requests for a cell within 50 ms become one fetch, missing or expired variables are fetched together, and identical in-flight fetches are shared. TTL per variable class (forecast current 15 min, air-quality current 60 min, fast 30 min, slow 60 min, astronomical 24 h); a dog's maxAge can only tighten it. On 429, 5xx, timeout or network errors, fully stored variables are served with `stale: true` instead of failing. Cache statistics keep working: every request counts exactly once through `getOrFetch` (upstream fetch shared for 60 s as a miss, served from the cell as a hit). In-process budget guard with the vendor weight rule `max(1, vars/10) * max(1, days/14)` and fixed limits 500/min, 4500/h, 9000/day: above them stored values are served with `stale: true`, an empty cell throws "Open-Meteo budget reached, retry in N s". New helpers `sliceDays`, `withStale`, `forecastCellRequest`, `openMeteoBudgetStatus`, `openMeteoCallWeight`, `OPEN_METEO_AIR_QUALITY_URL`. `openMeteoUrl` no longer rejects more than 10 hourly variables.
